# TaskHunt — план доведения до прода

Аудит проведён по факту (грепом по коду, не по памяти) 2026-07-28.
Дальше работают только Claude (оркестратор) и Gemini — см.
[`orchestration/README.md`](../orchestration/README.md).

## Текущий снапшот

Что реально готово и покрыто тестами: auth (email+OAuth), wallet/ledger
(double-entry, эскроу lock/release/refund), orders/bids/milestones/
delivery/reviews, чат с инвойсами, support-тикеты (бэк), admin RBAC +
разрешение споров, файлы (S3 + реальный ClamAV), реферальная программа,
notifications-service (реальный email через Resend) и fraud-service
(эвристический риск-скоринг) — оба воркера полностью рабочие. 47 юнит-
тестов, все зелёные. Фронт: лендинг, регистрация (с OAuth), онбординг,
логин, дашборд, страница заказа (чат + milestones + отзывы), админка,
рефералка.

Это солидный MVP. Но между "работает у нас на трёх заказах в докере" и
"можно пускать реальных людей с реальными деньгами" — разрыв, который
ниже разложен по приоритету.

## P0 — блокеры реального запуска

Без этого **нельзя** пускать пользователей с реальными деньгами.

### 1. Нет Prisma-миграций
`apps/api/prisma/migrations/` физически не существует — ни у одного из
трёх сервисов (api, notifications-service, fraud-service). Схема
накатывалась через `prisma generate`/неявный push, истории изменений
нет. Следствия: `prisma migrate deploy` (единственно правильный способ
прогнать схему в проде) не сработает — деплоить нечего; откат
невозможен; при первом же расхождении схемы между окружениями поймаем
даунтайм.

**Нужно:** `prisma migrate dev --name init` в каждом из трёх сервисов,
закоммитить `prisma/migrations/`, дальше — только через миграции, без
`db push` в prod-путях.

### 2. Вывод денег не работает по-настоящему
`WalletService.requestWithdrawal()` списывает `WITHDRAWABLE` и пишет
ledger-транзакцию `WITHDRAWAL` — и всё. Комментарий в коде честно
признаёт: "фактическая крипто-выплата — асинхронный процесс вне ledger
(воркер, который дёргает NOWPayments payout API)" — но этого воркера
физически нет. Пользователь запрашивает вывод, баланс списывается,
крипта никуда не уходит.

**Нужно:** воркер (BullMQ job на очереди `withdrawal-payouts`), который
по `WITHDRAWAL`-транзакции реально дёргает NOWPayments payout API,
и по неуспеху — откатывает деньги обратно через `REFUND`-транзакцию
(деньги никогда не должны "зависать" неопределённо).

### 3. Нет верификации email
`User.status` стартует как `PENDING_VERIFICATION`, но `submitOnboarding()`
переводит в `ACTIVE` просто по факту заполнения анкеты — без единой
проверки, что email вообще принадлежит регистрирующемуся. Любой может
зарегистрироваться на чужой адрес.

**Нужно:** таблица/поле для verification-токена, письмо со ссылкой
(через уже готовый notifications-service), эндпоинт подтверждения,
страница на фронте.

### 4. Нет восстановления пароля
Забыл пароль — тупик. Стандартный forgot/reset-password флоу отсутствует
полностью.

### 5. Нет rate limiting
`/auth/login`, `/auth/register`, `/wallet/invoices` и остальные открыты
без единого ограничения запросов — открытая дверь для brute-force и
спама.

### 6. Нет structured logging / error tracking
Везде голый `console.log`/Nest `Logger` (тоже в stdout). В проде это
означает: логи теряются при рестарте контейнера, нет корреляции
запрос→ошибка (request id), нет алертинга на 500-е. Нужен pino (или
аналог) + Sentry (или аналог) хотя бы на `apps/api`.

### 7. CORS открыт с дырой в WebSocket
`chat.gateway.ts`: `cors: { origin: '*' }` — любой сайт может открыть
WebSocket-соединение к чату от имени браузера залогиненного
пользователя. HTTP CORS в `main.ts` тоже: `origin: process.env.WEB_PUBLIC_URL ?? '*'`
— с дефолтом `*`, если забыть проставить env в проде.

### 8. Нет health-check эндпоинта
Ни `GET /health`, ни `/ready` — Docker healthcheck/будущий k8s liveness
не может определить, жив ли `api` (сравни с тем, что у `postgres`/`redis`/
`clamav` в `docker-compose.yml` healthcheck уже есть, а у `api` — нет).

### 9. Нет CI
Папки `.github/` нет вообще. 47 написанных тестов никто не гоняет
автоматически — можно сломать что угодно и не заметить до продакшена.

## P1 — важно для нормального UX (можно жить без этого первые дни, но не долго)

10. **Фронт: вывод средств.** Сейчас на дашборде `withdrawableBalance`
    только отображается цифрой — ни формы, ни кнопки запроса вывода нет.
11. **Фронт: редактирование профиля.** Бэк (`PATCH /users/me/profile`)
    готов давно, страницы для этого на фронте нет вообще.
12. **Фронт: тикеты поддержки.** Бэк полностью готов
    (`support.controller.ts`), фронтенд-страницы нет.
13. **In-app уведомления.** Уведомления сейчас уходят только в email —
    внутри самого приложения (колокольчик/список) их не видно.
14. **Admin: управление категориями/навыками.** Сейчас только через
    `prisma/seed.ts`, менять/добавлять категорию можно только руками в БД.
15. **Admin: дашборд с метриками.** Выручка, активные споры, воронка
    заказов — ничего этого нет, только списки users/disputes/flags.
16. **Поиск и фильтры по заказам.** `GET /orders` фильтрует только по
    `categoryId`/`status`, полнотекстового поиска по названию/описанию
    нет.
17. **E2E-тест критического пути.** Юнит-тесты покрывают сервисы
    изолированно (с моками Prisma) — нет ни одного теста "от регистрации
    до вывода денег всё работает вместе" на реальной тестовой БД.
18. **Graceful shutdown в `apps/api`.** В notifications-service и
    fraud-service `SIGTERM`-хендлер уже есть (закрывают worker/prisma/redis
    по-человечески), в главном API — нет.

## P2 — усиление и полировка

19. Тестовое покрытие того, что ещё не тронуто: `auth.service.ts`,
    `chat.service.ts`, `files.service.ts`, `catalog.service.ts`,

    `$transaction` действительно защищает от double-spend при гонке.

    видимость на упавшие джобы только через логи.
22. Legal: Terms of Service, Privacy Policy, cookie-consent — обязательно
    при работе с деньгами/криптой, сейчас нет ни одной страницы.
23. SEO для публичных страниц заказов (`GET /orders` не требует auth —
    значит каталог заказов теоретически индексируемый, но метатегов/
    server-side rendering под это не настроено).
