# TaskHunt — Готовность к продакшну

Платформа **уже развёрнута и работает** на `taskhunt.lol` (Azure VM, nginx + Docker Compose, SSL от Let's Encrypt). Этот документ — не гипотетический чек-лист "что нужно сделать перед запуском", а снимок реального текущего состояния: что настроено и подтверждено работающим, что осознанно оставлено пустым и почему. Runbook самого деплоя — [DEPLOYMENT.md](DEPLOYMENT.md), обзор архитектуры — [ARCHITECTURE.md](ARCHITECTURE.md).

---

## 1. Что подтверждено работающим на реальном домене

### Инфраструктура
- SSL-сертификат (Let's Encrypt) на все 4 поддомена, автопродление через certbot timer.
- `taskhunt.lol` / `www.taskhunt.lol` (301→apex) / `api.taskhunt.lol` / `admin.taskhunt.lol` (301→`apex/admin`) — все проверены `curl -I`.
- WebSocket-проксирование в nginx для чата (сообщения доставляются мгновенно, без отката на polling).
- Все 5 сервисов (`api`, `web`, `notifications-service`, `fraud-service`, плюс `postgres`/`redis`) стабильно держатся без краш-лупов.

### Почта и уведомления
- Resend (`RESEND_API_KEY`) настроен, домен верифицирован (DKIM/SPF/DMARC в Cloudflare DNS).
- Email-верификация — полный цикл: регистрация → письмо со ссылкой → экран "Подтвердите почту" после онбординга → переход по ссылке → `ACTIVE`. Есть кнопка повторной отправки (`/auth/resend-verification`) и на этом экране, и постоянная плашка в шапке, пока аккаунт не подтверждён.
- Сброс пароля — тот же паттерн (email со ссылкой, токен с TTL).

### OAuth
- Google и GitHub — оба настроены и подтверждены живьём (`/auth/google`, `/auth/github` редиректят с реальным `client_id` на верный callback-домен).
- Apple OAuth — код есть (`AppleInitGuard`), реальные credentials не выданы.

### Аналитика
- Google Analytics 4 (`NEXT_PUBLIC_GA_MEASUREMENT_ID`) — подключена через `@next/third-parties`, с полным Google Consent Mode v2 (`default: denied` до явного согласия в cookie-баннере).
- Cloudflare Web Analytics — если включена в панели, беакон разрешён в CSP.

### SEO
- Уникальные `title`/`description`/`canonical` на всех публичных страницах, JSON-LD (`Organization`, `WebSite`, `Product`/`Offer` для тарифов, `ItemList` для категорий, `Person` для профилей фрилансеров).
- `noindex` явно на всех приватных/служебных страницах (не только через `robots.txt` — см. [ARCHITECTURE.md §9](ARCHITECTURE.md#9-инфраструктура-и-деплой) про конфликт групп `User-agent: *` от Cloudflare).
- `sitemap.xml` генерируется динамически (категории, фрилансеры, открытые/завершённые заказы).

### Безопасность
- 2FA/TOTP с бэкап-кодами, rate limiting на чувствительных роутах, ClamAV-скан загружаемых файлов.
- Приватные страницы (`/dashboard`, `/profile`, `/chats`, `/admin`, `/support`, `/onboarding`) редиректят анонима на `/login?redirect=<путь>` вместо показа сломанной страницы.
- Staff-аккаунты (`isStaff: true`) исключены из всех публичных списков — поиска, ленты заказов, публичной статистики.
- Сообщения откликов (`Bid.message`) видны только заказчику заказа и автору конкретного отклика — не другим фрилансерам-конкурентам.
- `POSTGRES_PASSWORD` — сгенерированный секрет, не дефолтный dev-пароль из `docker-compose.yml`.

## 2. Осознанно не настроено (пусто в `.env`, не баг)

| Что | Влияет на | Как включить |
| :--- | :--- | :--- |
| `NOWPAYMENTS_API_KEY` / `NOWPAYMENTS_IPN_SECRET` | Депозиты, вывод, оплата инвойсов/подписок/бустов криптой — везде отдаёт `503 Платёжный провайдер временно недоступен` | Получить ключи в кабинете NOWPayments, прописать в `apps/api/.env`, пересоздать контейнер `api` |
| `S3_*` (endpoint/bucket/ключи) | Загрузка аватаров и файлов к спорам | Поднять S3-совместимое хранилище (или Cloudflare R2/Backblaze), прописать в `apps/api/.env` |
| Apple OAuth credentials | Кнопка "Войти через Apple" | Apple Developer Program, `AppleInitGuard` уже готов принять реальные ключи |

## 3. Мониторинг и бэкапы — не настроено, следующий шаг

Это единственный реальный пробел, а не "уже сделано, но не описано":

- **Логи**: Pino-логгер пишет JSON в stdout контейнеров (`docker compose logs`), но никуда не агрегируется — нет Grafana Loki / Datadog / Elasticsearch.
- **Ошибки**: нет Sentry (или аналога) ни на API, ни на web — необработанные исключения видны только в логах контейнера, если их кто-то читает.
- **Бэкапы БД**: нет автоматического `pg_dump` по расписанию — данные существуют только в Docker-волюме `postgres_data` на одном VPS.
- **BullMQ Board**: очереди (`withdrawal-payouts` и др.) не имеют визуального монитора для админов — только логи воркеров.

Приоритет для реального продакшна с деньгами пользователей — бэкапы БД в первую очередь (даже простой ежедневный `pg_dump` + выгрузка в отдельное хранилище закрывает самый дорогой риск — потерю данных о балансах/эскроу).
