## 2. История операций (леджер)

Сейчас на дашборде — только текущие остатки (`MAIN`/`ESCROW`/`LOCKED`/
`WITHDRAWABLE`/`PENDING`), нет журнала "что произошло с деньгами".
Источник правды — `LedgerTransaction`+`LedgerEntry`
(`schema.prisma:440-469`) — тут уже лежит вся история (эскроу
залочен/выплачен/рефанднут, комиссии, вывод средств), просто наружу
никогда не отдавалась.

### Бэкенд

`apps/api/src/modules/wallet/wallet.service.ts` — новый метод
`getTransactionHistory(userId: string, cursor?: string, limit = 20)`:
- Найти `walletId` пользователя (`this.prisma.wallet.findUniqueOrThrow({ where: { userId } })`,
  см. паттерн в `getBalances` строка 16).
- `this.prisma.ledgerEntry.findMany({ where: { walletId }, include: { transaction: true }, orderBy: { createdAt: 'desc' }, take: limit + 1, ...(cursor && { cursor: { id: cursor }, skip: 1 }) })`
  — курсорная пагинация (offset на больших объёмах хуже), `take: limit + 1`
  чтобы понять, есть ли следующая страница (стандартный трюк, `nextCursor = items.length > limit ? items.pop()!.id : null`).
- Смаппить в плоский вид для фронта: `{ id, type: transaction.type, direction, balanceType, amount, currency, description: transaction.description, referenceType: transaction.referenceType, createdAt }`.

`wallet.controller.ts` (`@Get('balance')` уже есть, строка 56) —
добавить рядом `@Get('transactions')`:
```ts
@Get('transactions')
getTransactions(@CurrentUser() user: AuthenticatedUser, @Query('cursor') cursor?: string) {
  return this.walletService.getTransactionHistory(user.id, cursor);
}
```

Тест: `wallet.service.spec.ts` — курсорная пагинация отдаёт
`nextCursor: null` на последней странице, `LedgerDirection`/`BalanceType`
корректно прокидываются в ответ.

## 4. Смена пароля

Сейчас смена пароля возможна только через "Забыли пароль" (email со
ссылкой). Добавить прямую смену из настроек — быстрее, не гоняет юзера
через email ради тривиального действия.

### Бэкенд

`auth.service.ts` — паттерн `bcrypt.compare` уже используется в login
(строка 159), `bcrypt.hash` — при регистрации/сбросе (строки 40, 144).
Новый метод `changePassword(userId: string, currentPassword: string, newPassword: string)`:
- Найти юзера, `bcrypt.compare(currentPassword, user.passwordHash)` —
  если не совпало, `BadRequestException('Неверный текущий пароль')`.
- `newPassword` — минимум 8 символов (та же валидация, что в
  `RegisterDto`, проверить `dto/register.dto.ts` на точные правила и
  продублировать в новом DTO).
- `bcrypt.hash(newPassword, BCRYPT_ROUNDS)`, обновить `passwordHash`.

`auth.controller.ts` — `@UseGuards(JwtAuthGuard)` `@Post('change-password')`,
`@Throttle({ default: { limit: 5, ttl: 60000 } })` (это по сути
подбор пароля, если бы не требовался текущий — с текущим паролем риск
ниже, но лимит всё равно не помешает, дёшево поставить).

Тест: неверный текущий пароль → `BadRequestException`, успешная смена
→ новый хэш действительно проверяется через `bcrypt.compare` в тесте
(не просто "метод вызван", а что хэш реально валиден).

### Фронтенд

`profile/page.tsx` — новая секция "Безопасность" (ещё один блок в том
же файле, см. п.1 про порядок правок) — три поля (текущий пароль,
новый пароль, повтор нового), клиентская проверка "новый === повтор"
до отправки, успех/ошибка тем же паттерном, что остальные секции
профиля (`saved`/`error` state).
