# TaskHunt — ТЗ для себя (Claude), раунд 11: категории/навыки/поиск — новые страницы + иконки

Раунд про "сайт выглядит пустым" — пользователь показал скриншот
work.ua (страница "Пошук вакансій за категоріями": сетка категорий со
счётчиками + карточки-шорткаты "по городам/компаниям/посадам") и
попросил аналог, только круче, плюс общий upgrade поиска, плюс новые
страницы, продуманные до мелочей. **Ключевое условие: никаких эмодзи в
дизайне — только кастомные SVG в нашем чернильном стиле** (см.
`components/icons/illustrated/`), и их должно стать заметно больше, по
смыслу на каждую категорию/раздел.

Раздел ответственности в этом раунде особый: **я — весь UI/UX
(фронтенд) + по минимуму бэка** (только контракты, которые проще
сделать самому, чем описывать словами), **Gemini — весь бэкенд этого
раунда** ([`TZ_GEMINI_11.md`](./TZ_GEMINI_11.md)). Обычной для нас
логики "деньги/реалтайм — мне, остальное — Gemini" здесь нет: ничего
денежного в раунде вообще нет, просто в этот раз бэк отдаю целиком.

**Зависимость от Gemini**: три страницы ниже (`/categories`, `/skills`,
`/search`) рассчитаны на новые поля/эндпоинт из `TZ_GEMINI_11.md`
(`orderCount` у категорий, `usageCount` у навыков, `GET /search`).
Пока Gemini не сдал — верстать и проверять на текущих данных без этих
полей (просто не показывать счётчик/бейдж, если поля нет,
`category.orderCount ?? null`), не блокироваться. `/search` может
first-pass работать полностью на фронте через уже существующие
`GET /orders?search=` + `GET /freelancers?search=` парой параллельных
запросов — переключить на `GET /search` одной строкой, когда Gemini
сдаст, оставить как fallback работать уже сегодня.

## 2. Страница `/categories` — витрина категорий

Аналог work.ua-скриншота, но в нашей стилистике: карточки вместо
плоского текстового списка (у нас и так уже плитки на других
страницах — единообразие).

- 5 топ-категорий — крупные карточки (иконка через `CategoryIcon`,
  название, счётчик "N открытых заказов" из `category.orderCount`),
  внутри каждой карточки — подкатегории мелкими текстовыми
  чипами-ссылками (не отдельные иконки на каждую подкатегорию, это

- Клик по карточке или подкатегории → `router.push('/dashboard?categoryId=' + id)`.
- Наверху страницы — свой `SearchIcon` + инпут, ведущий на `/search?q=`
  (Enter или кнопка) — та же логика входа, что будет в шапке (п.4), но
  здесь уместна крупная центральная версия, как на скриншоте work.ua.

## 3. Страница `/skills` — облако навыков

- Все навыки из `GET /skills` (уже включая пользовательские, которые
  фрилансеры сами создали через `POST /skills` из раунда про профиль),
  отсортировать на фронте по `usageCount` desc.
- Рендер — теговое облако: размер шрифта чипа пропорционален
  `usageCount` (3-4 стъпени размера, не буквально линейно — иначе один
  выброс визуально сломает сетку), иконка `TagIcon` перед самым частым
  десятком, дальше просто текстовые чипы.
- Клик по навыку → `router.push('/freelancers?skillId=' + id)`.
- Пустое состояние (если вдруг `usageCount: 0` у всех — свежая БД) —
  `EmptySearchIcon` + текст "Пока никто не указал навыки".
