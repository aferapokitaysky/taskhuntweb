# Оркестрация: как здесь работают несколько агентов параллельно

Этот проект (TaskHunt) собирают одновременно несколько AI-агентов в одной
физической папке на диске. Чтобы не мешать друг другу и не терять
контекст между сессиями (у каждого агента своя память, они не видят чужих
разговоров), используется файловый протокол вместо живого чата.

## Схема

Для каждого агента, у которого есть отдельная зона ответственности,
заводится пара файлов:

- **`TZ_<AGENT>.md`** — техническое задание. Пишется один раз в начале
  (или обновляется при пересмотре скоупа), содержит весь контекст,
  необходимый агенту для старта работы без доступа к остальному
  разговору: архитектура, что уже сделано, что делать, справочник API,
  definition of done.
- **`STATUS_<AGENT>.md`** — рабочий журнал, который **ведёт сам агент** по
  ходу работы: свой TODO-список, что в процессе, что готово, вопросы к
  оркестратору (если чего-то не хватает или неоднозначно). Оркестратор
  (сейчас это Claude, ведущий разговор с пользователем) периодически
  перечитывает эти файлы и отвечает прямо в них, в секции "Ответы
  оркестратора" — так же, как это уже работало через
  `docs/MISSING_ENDPOINTS.md` между Claude и Codex.

## Codex вышел из проекта

Codex больше не участвует. Всё, что он успел сделать, закоммичено
(включая `notifications-service`, `fraud-service` и последний фикс
`onboarding` — он их не закоммитил сам, доделал за него оркестратор).
Незакрытые им фронтенд-задачи (страницы `oauth/callback` — уже сделаны
оркестратором, UI для milestones/delivery/reviews — ещё нет) переходят
к оставшимся участникам. `docs/TZ_CODEX.md` и `docs/MISSING_ENDPOINTS.md`
оставлены как есть — исторический контекст, не удаляем.

С этого момента над проектом работают только **Claude (оркестратор)** и
**Gemini**.

## Правила, чтобы не было конфликтов на диске

1. Каждому агенту — своя, по возможности **новая**, не пересекающаяся
   с другими зона файлов. Если зона всё же пересекается с чужой (общий
   файл вроде `docker-compose.yml`, `app.module.ts`, `packages/shared-types`)
   — агент не редактирует его напрямую, а описывает нужное изменение в
   своём `STATUS_<AGENT>.md`, и правку вносит оркестратор.
2. Перед началом работы — прочитать текущий `git log --oneline` и
   `git status`, чтобы понимать, что уже сделано и что сейчас в процессе
   у других (см. `docs/CONTRIBUTING.md` про ветки/worktree).
3. Коммиты и весь текст в этих файлах — на русском.
